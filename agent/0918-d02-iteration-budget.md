# D02：按迭代轮次检查评价预算

2026-09-18，用户确认：“我觉得按照迭代轮次来 不用实时验证”。

## 已采用规则

- `maxFEs` 是迭代边界的停止阈值，不是逐次评价的硬上限。进入一轮前检查；已开始的轮次完整执行，再在下一轮入口判断。
- 初始化完整执行，实际评价计入 FEs。即使预算小于初始种群，也不缩小初始化或报预算不足；初始化后达到阈值就不开始迭代。复用完整预评价种群的既有免评价规则不变。
- `maxIters` 仍独立限制完成的迭代轮数；停滞等既有停止条件保留。算法因无新候选等自身条件提前停止的行为不变。
- 运行结果记录实际 FEs，不截成 maxFEs。每轮评价量由算法决定，不承诺最多只超出一个 nPop。

## 修改

多数算法已在 `checkTermination` 检查边界，本次仅移除两处例外：MOEAD 的轮内逐个体预算中断，MOASMO 按剩余预算缩减 infilling 数量。MOASMO 的候选去重与有限域处理继续保留，不为填满一批重复评价。

中英文 API 同步说明初始化、末轮和实际计数语义。没有将 maxFEs 换成 maxIters，也没有改变评价次数统计方式。

## 验证

- 新增 GA/MOEAD 共 12 项边界测试，预算为 0、3、8、9、16、19 时，8 个初始个体对应实际评价数为 8、8、8、16、16、24；同时核对实际回调行数及完成轮数。
- MOEAD 的四种聚合方式均验证预算 19 时完成 24 次评价、2 轮迭代。
- MOASMO 实际代理训练/嵌套优化测试使用 nInit=8、maxFEs=9，完整评价两个新候选后 FEs=10，并核对预测坐标与真实评价。
- 相关测试 72 项通过；全量 **1401 passed，4 条原有 FAST warnings，20.65 秒**，结果见 [验证日志](verification/0918-d02-pytest.txt)。
